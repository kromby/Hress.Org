# Add a Beer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Members can add a beer to the current season from `/beer/register`, either by picking an existing catalog beer or by creating a new one with a photo of the can as its cover.

**Architecture:**
- The API gets a `BeerCatalogInteractor` in `Ez.Hress.BeerRater`, with three operations: search the catalog, add an existing beer to a season, and create a beer in a season. They're exposed by a new `BeerCatalogFunctions` class.
- The page is a new `src/pages/beer/register.tsx`. It gets data through new hooks in `useBeerApi.ts`, and uploads photos through `hress.tsx`, the only file under `src/pages/beer` that may use the rest of hress.org.

**Tech Stack:**
- API: .NET 9 isolated Azure Functions, Azure Table Storage, xUnit + Moq.
- Frontend: React 19, TanStack Query v5, Axios, Jest + Testing Library (`npm test`, react-app-rewired).

**Spec:** `docs/superpowers/specs/2026-11-07-add-a-beer-design.md`

**Delivery:** four PRs, one per BeerRater sub-issue, each on its own branch from `main`, merged in order:

Part 1 uses the existing branch `claude/beerrater-add-beer`, which already holds the spec and this plan. Each PR body says `Part of kromby/BeerRater#8` and closes its sub-issue. Part 4's PR also closes kromby/BeerRater#8, #9 and #10.

## Global Constraints

- Name, producer and country are required, and can't be blank after trimming. Alcohol % is required, must be > 0 and ≤ 20.
- Vínbúðin link, style and description are optional. A Vínbúðin link, if given, must be an absolute `https` URL.
- Max lengths (my call, the spec leaves them to the builder):
  - name, producer, country, style: 100
  - vinbudinUrl: 500
  - description: 2000
- Photos go to hress.org album **46153** using the `Album` image container (`ImageContainer.Album`), not `ImageContainer.Beer`.
- New beer IDs: 10 characters from lowercase `a-z0-9`, random.
- Only the open season accepts writes. A closed season gives `SeasonClosedException` → 409.
- Duplicate guard: the same normalized name **and** producer gives 409, and the response body is `{ "duplicate": <beer> }`.
- Name normalization, used by both search and the duplicate guard:
  - trim, collapse runs of whitespace to one space, lowercase (invariant culture);
  - strip diacritics (NFD, then drop non-spacing marks);
  - map `ð→d`, `þ→th`, `æ→ae`.
- Search matches when the normalized name contains the normalized query. Results are sorted by name with `is-IS` collation, at most 10. A query shorter than 2 characters after trimming returns an empty list.
- Logging: `[{Class}.{Method}] message`. All DI registrations are singletons in `Program.cs`.
- Frontend copy, verbatim:
  - Title "Skrá nýjan bjór"; matches "Bæta við" and "er á tímabilinu".
  - Hint "Finnurðu hann ekki? Haltu áfram að skrá hann."
  - Photo button "Taka mynd af dósinni"; save button "Skrá bjór".
  - Labels "Nafn", "Brugghús", "Land", "Styrkleiki %", "Vínbúðin (valfrjálst)", "Tegund (valfrjálst)", "Lýsing (valfrjálst)".
- Prettier: double quotes, trailing commas (es5), 2-space indent. No horizontal scroll at 375px.

## Review Focus

1. **Comma decimals:** Icelandic users type alcohol % as `5,4`. The form must accept it as 5.4. Test in Task 9: `validateNewBeer accepts a comma decimal`.
2. **Double taps:** tapping "Skrá bjór" or "Bæta við" twice must not create or add twice. Both are disabled while pending. Tests in Task 7 (`disables Bæta við while adding`) and Task 9 (`disables Skrá bjór while saving`).
3. **Spacing duplicates:** "Jóla  Kaldi " from "Bruggsmiðjan Kaldi" is the same beer as "Jóla Kaldi" from "bruggsmiðjan kaldi". Test in Task 4: `Create_SameNameAndProducerDifferentSpacingAndCase_ThrowsDuplicate`.
4. **Special characters in the query:** a query like `Jóla & Co` must reach the API intact. Test in Task 6: `useCatalogSearch encodes the query`.
5. **Season closes mid-form:** if the season closes between loading the page and saving, the 409 shows "Tímabilið er búið og ekki hægt að skrá bjór." and keeps the input. Test in Task 9: `shows the closed message and keeps input when the season closed meanwhile`.
